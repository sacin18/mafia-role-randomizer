I want to create a very simple html page/app to assign nad play mafia game. It should first ask users to enter a game-code with auto-type (it should also show currently running games as a drop down). Game codes can be created only when game-god creates a new game. 

When game-god selects create game -- a random game-code is generated with random words similar to how docker names its containers instead of simply having som uuid (like pip install names-generator library). they get to set a passcode (4-8 digits), number of mafia members, names of all players (can also be auto-filled by previous runs for the same game code), number of detectives, number of doctors, number of villagers.  The total number of players will be mafia + detective + doctor + villagers. Optionally -- god can allow players to join and once god wants to begin - they can using a percentage randomly assign mafia, doctors, detectives, villagers.
Once the number of players are confirmed, the game god can click on "Begin Randomization". Then the app will assign roles randomly to each player and show the roles to each player on their device can refresh the page to view their roles. 

Only using game-god with game-code + passcode can modify the game rules (like kill/save mode,etc), also only god can see the role assignments of all players, each individual player will only be able to see their own role.

Individual players can add themselves to the game - they need to enter the game code and their player name (if the player name is already taken in the game code, then it should show an error). Also, the game code should be cached in browser storage, so that the next time they open the web page - they can just enter their name and have their last game code as default selected game code from the list. They can optionally type or select the game code from the dropdown.

Since this is a client-side only app, it should be very simple, it should work on the browser, and it should use web-socket to communicate between the client and the server.

I want the app to be very responsive and the design to be very modern and simple. It should be easy to use and understand.

The game is meant to be played in a low signal/no internet setting. All players and god will be using mobile phones. The god's webpage can be an android app if required (I would prefer if it is a simple webpage or can be run as a progressive web app). Intention is that that god's phone will act like the server and others can connect to the god's hotspot and play the game. So, all data is stored on the god's phone and can be refreshed to see the latest data. No external database or server should be used. (god's phone will have a static IP, other devices will use that to connect to the server. god can see a list of all players, all other players will only be able to see their own role. Also if a player refreshes, they should be able to see their role if game has not started, if game has started - they should not be able to see their role).
